Offline Translation Device

In Progress

A fully offline speech translation device — no internet dependency, no lag.

photo: Raspberry Pi setup
photo: early test rig
Problem

Repeatedly heard taxi drivers in China describe how existing online translation tools slowed conversations to a crawl — dependent on signal, laggy, and unreliable exactly when needed most.

Constraints

No prior experience with embedded AI. Needs to run fully offline on low-power hardware, in real time.

Approach so far

Sourced a Raspberry Pi as the compute base. Selected Whisper as the open-source speech recognition foundation. Currently teaching myself the embedded AI pipeline from scratch — breaking the problem into pieces I can validate one at a time.

Status / next steps

Early build phase. Updates as the prototype takes shape.

PongPong — Mahjong Keepsake Device

MVP Built — Parked

A mahjong tile-shaped keychain that stores and plays back friends' voices — built, tested, then deliberately shelved.

photo: 3D printed enclosure
photo: PCB
photo: final assembly
Problem

Inspired by nightly mahjong games during my exchange at NUS — a shared ritual that disappears when everyone scatters back to different countries and cities. Wanted to preserve it.

Constraints

ESP32 with only 320KB of RAM. Needed to process and store audio files far larger than that RAM budget allowed, while keeping response logic snappy for press / hold / release interactions.

Solution

Built a functioning MVP in under two weeks. Designed and 3D printed the enclosure, then built an audio processing algorithm that splits a single recording into separate "ma" / "aaah" / "jong" components, so the device responds differently depending on how the button is pressed. Used multiple pass-throughs to compress and process audio that would otherwise have exceeded the ESP32's memory limit. Used AI tools to accelerate learning unfamiliar areas — PCB design and digital audio processing — fast enough to keep pace with the build.

What changed

Mentors and friends liked the product but consistently asked: "Why does this need to be a startup?" Rather than defending it, I treated the feedback as data. I'd validated whether I could build it — not whether I should. Parked it within a week and pivoted to the translation device above.

Lesson

Speed of learning beats speed of building. Building fast only matters if you're also willing to find out fast that you're wrong.
